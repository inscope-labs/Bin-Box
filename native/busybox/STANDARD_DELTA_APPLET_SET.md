# Standard-Delta Applet Set (RTX-100 Phase 2.1b)

## What this is
BusyBox already implements 22 of Standard tier's original 26-tool
candidate list as applets. Rather than treat those as new toolset
sourcing (Phase 2.1-2.5 proper), they ship as a second, smaller BusyBox
build — a "delta" build containing only these 22 applets, layered on top
of Base's always-present 13. This is real work (verified via host build,
this doc), but categorically cheap compared to a fresh cross-compile per
tool.

## Applet list (22)
`grep sed awk find du df stat tar gzip unzip wget ping less head tail wc
sort uniq cut diff xargs tee`

## Deliberately excluded (this is a delta, not a superset)
All 13 Base applets (`ash/sh ls cp mv rm mkdir cat chmod ps kill env
which uname`) are explicitly OFF in `standard-delta.config`. Base's own
binary/symlinks already provide these and are permanently present
(confirmed with John: Base is the non-removable foundation) — duplicating
them into a second binary would waste DFM download size for no benefit.

**Non-obvious gotcha found during Kconfig resolution:** `CONFIG_SH_IS_ASH`
and `CONFIG_SHELL_ASH` are separate switches from the `ASH` applet toggle
itself, and `SH_IS_ASH` defaults to **on** even starting from
`allnoconfig` — silently pulling `sh` back into the applet list even with
`ASH` off. Config must explicitly set `CONFIG_SH_IS_NONE=y` (verified in
`standard-delta.config`) or the delta build ships a duplicate `sh`
alongside Base's. The build workflow (`build-busybox-standard-delta.yml`)
fails loudly if this regresses.

## Verified (host build, x86_64/glibc, same method as Phase 1.4)
- Clean build, no errors.
- Dependency closure identical to Base: crypt/m/rt all excluded as
  unneeded — no extra shared libraries required beyond bionic libc on
  the real Android cross-compiles.
- `make install` produces exactly 22 applet symlinks, zero overlap with
  Base's 13/14 (no `sh`/`ash` present).
- Install-layout split (`bin/` vs `usr/bin/`) is the same non-issue noted
  for Base — irrelevant to this project since applet-name symlinks are
  generated by the app itself (Phase 4.4), not by running BusyBox's own
  `make install` on-device.
