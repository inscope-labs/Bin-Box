## 2. What Changed

`ui/components/SettingsScreen.kt`: 671 lines -> 155 lines (Orchestrator).

New `ui/components/settings/` package, 10 Module files, none over 170

`OciCloudSection.kt` (35L), `BetaTestingSection.kt` (69L),
`DiagnosticsSection.kt` (71L), `SystemTelemetrySection.kt` (61L).

Each section's UI body was extracted via precise line-range copy from the
original file (not retyped from memory) to guarantee byte-for-byte
fidelity of the actual rendering logic, then wrapped in a
`@Composable fun XSection(...)` taking exactly the state/callbacks it
needs as parameters. `SettingsScreen.kt` now only holds state
(`collectAsStateWithLifecycle`, `remember`) and wires it into each
section — no rendering logic of its own beyond the small `DetailRow`
helper, which stayed in place since `SystemTelemetrySection` still calls
it.

**One real code change, not just a move**: `BetaTestingSection` and
`DiagnosticsSection` originally called `BetaEnrollment.setEnrolled(...)`
and `CrashReporterManager.updateReportingPreference(...)` directly inside
their own `onCheckedChange`. Since these are now Module files, that
would have made them own persistence, violating the Orchestrator/Module
split (Module = render + delegate, not own side effects). Both were
converted to controlled components — `onEnrolledChange` /
`onReportingEnabledChange` callbacks — with the actual persistence calls
moved to `SettingsScreen.kt`, where they already were reachable. This is
a structural correction required by the split itself, not a behavior
change: the toggles do exactly what they did before, just wired through
a callback instead of a closure.
